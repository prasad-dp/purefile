- Next: Feature 14 — Secure Vault (biometric lock, AES-GCM encryption at rest, auto-lock).
- Feature 14 done. Trust model, stated honestly: files + manifest are AES-256-GCM under a random 256-bit vault key; the key is WRAPPED by a PBKDF2-HMAC-SHA256 (150k iters, random salt) key derived from the user secret; only the wrapped blob lives in flutter_secure_storage (Keystore/Keychain backed); biometrics gate the SESSION — they never derive the key, so removing a fingerprint can't lose data and a forgotten secret is unrecoverable (copy says so up front).
  • `core/vault/vault_crypto.dart` (pure Dart, no platform): wrap/unwrap key (blob salt(16)||cipher(32)||mac(16)||nonce(12); wrong secret → ArgumentError, malformed → StateError), encrypt/decrypt file blobs (cipher||mac||nonce), PBKDF2 150k, `Random.secure()`. **cryptography-2.9 API gotchas**: `SecretKeyData` (no SecretBytes), `SecretBox(cipher, nonce:, mac:)`, `Mac.bytes`, cascade-on-BytesBuilder must be assigned first (`final b = BytesBuilder()..add(); return b.toBytes();` — the chained `.add().toBytes()` form made the cascade swallow the call and return the builder itself).
  • `core/vault/vault_store.dart` — vault dir `documents/vault/`: `manifest.pfv` (encrypted JSON list — file NAMES are never on disk in plaintext) + `<32-hex-id>.pfv` blobs (ids, not names). `importFile` caps 100 MB (typed FileTooLarge; truncate-extend test trick keeps the fixture instant), encrypts via atomic write, THEN secure-deletes (3-pass overwrite) the original — import order guarantees no data loss window. `exportTo` decrypts under the original name through uniqueDestination; `remove` secure-deletes the blob; `reset` verifies the secret by unwrapping BEFORE destroying anything. Two-level lock: **hard** = key dropped (secret re-derives), **soft** = key kept in memory (biometrics re-gate). `VaultKeyStorage` interface + `InMemoryKeyStorage` for tests.
